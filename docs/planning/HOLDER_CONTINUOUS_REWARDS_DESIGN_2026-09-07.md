# 持有人 24 小时连续收益：设计与实现边界

日期：2026-09-07。状态：用户已批准并已实现合约/前端接线；尚未广播，也未完成测试网验证。本文件不代表生产完成。

## 目标与保持项

取消普通持有人等待七天周期、请求 Root、等待发布审核及获取 Merkle proof 的领取依赖。钱包持有 meme 即可参与，已累计收益随时领取；转出本金不清除已赚收益。

既定经济规则保持：开启持有人分配时，从扣除 Creator tax 后的创建者 BASE 手续费份额分出 50% 给持有人；Creator tax 仍全归创建者。平台、股票质押者和创建者其余收益保持独立账本与路径。持有人收益继续使用市场 Quote；内部兑换完成之前不能把预估产出作为可领取余额。

## 当前实现证据

本轮实现位于 `HolderRewardsDistributorV1.sol`、`TickerMemeTokenV1.sol` 及 `V1DeterministicDeploymentBuilder.buildContinuous`。以下规则以这些源码为准。

- `contracts/src/v1/modules/TickerMemeTokenV1.sol`：连续模式开启后，余额更新前调用分配器检查点；固定供应量直接铸入 Curve；仅允许指定 Treasury 销毁自身持有的 meme。旧 Token 不会被改写。
- `contracts/src/v1/modules/HolderRewardsDistributorV1.sol`：每笔到账资金独立按 24 小时线性流式释放；最多 64 条并发 stream。容量不足时本次 FeeVault funding 回退，待资金再次重试；不影响转账或用户领取。供应为零时进入 idle，之后有有效供应且有容量时重新开启一条 24 小时 stream。
- `contracts/src/v1/shared/ProtocolFeeVaultLiabilities.sol`：`_creditTradingFeeLiabilities` 将扣除 Creator tax 后的创建者份额折半记入 `holderLiability[marketId][epochId][asset]`；`fundHolderRewards` 将 Quote 划入分配器。
- `contracts/src/v1/shared/ProtocolFeeVaultCurveCredit.sol`：Curve sweep 经过实际余额差校验，再记录负债。当前记账时点不是每笔原始交易时点。
- `contracts/src/v1/shared/ProtocolFeeVaultRewardSettlement.sol`：`settleHolderRewards` 先将 meme 换成 Quote，原收益归属依赖 epoch。
- `docs/v1/V1_TREASURY_ARCHITECTURE.md`：持有人分配基于七天 Transfer 历史 TWAB 和独立发布、审核、领取状态机。

所以不能只把七天常量删掉：需要新增 Token 转账检查点和收益累计器，并重接 FeeVault、部署、API 与 Rewards 页面。

## 已批准并实现的经济规则

### 实际到账资金持续释放（24 小时）

真实到账 Quote 进入未释放储备，按时间释放给当时有效持仓；转账前更新全局指数及双方收益债务。用户领取已累计部分，不等待全部资金释放完成。

核心账本：未释放储备、每单位累计收益、有效供应量、账户收益检查点、账户已赚未领金额。更新时间与转账、资金入账、领取结合；无交易时 view 按时间推算，下一次写操作追记，不需要每秒发交易。

用户收益近似为积分：余额占有效供应量的比例 × 当时释放速率 × 时间。这里依然使用时间，只取消七天整期结算。

经济差异必须说明：新持有人参与买入后尚未释放的奖励；旧持有人卖出后只保留已赚部分。它不是追溯给手续费发生时的旧持有人分红。延后归集仍影响谁参与释放，并未消除所有时机影响；不能宣传消除所有 MEV。

24 小时不是锁仓期，也不是必须等待 24 小时才能领取。它是每笔待释放资金的分配节奏。每笔 funding 有独立结束时间；追加资金不会重置既有 stream 的 deadline。源码的 bucket 1 只是兼容性编号，永远不是 epoch 或时间周期。

## 架构约束

1. 仅实际、可核验到账的 Quote 支持发行收益；兑换失败只保留待兑换资产，不能虚记收益。
2. Token `_update` 在余额变化前处理旧余额对应的收益，余额变化后更新有效供应量。买入、卖出、转账、零额、自转、mint、burn 必须明确顺序。
3. 转账路径只能做有界记账，不在其中兑换、领取、任意外部转账或扫描持有人；开关关闭的市场不走持有人路径。
4. 排除 Curve、PoolManager、Locker、分配器及明确列出的协议库存，不能把池子库存当普通持有人余额。排除集合与变更权限须冻结；不能在收益分配期间任意变动而不结算旧状态。
5. 零有效供应时不把过去闲置时段的收益一次性送给第一位买家；资金保持有账可查，恢复参与后的释放规则必须明确。
6. 用户转出、卖光后保留已累计收益。禁止领取时要求仍有余额，或将卖家已赚收益附在代币上转给买家。
7. 高精度累计与余数需要跨操作保留；频繁小额 checkpoint 不能使释放永久舍入为零。总可支付金额不得超过入账金额减去已支付金额。
8. 领取遵循先更新负债后付款、重入保护、付款失败原子回滚。失败不能污染其他用户账本。
9. 分配器检查点影响 ERC-20 转账可用性，不能采用任意可替换的不可信回调；验证初始化顺序、授权和异常状态，不能用静默 catch 丢弃收益记录。
10. 当前已部署 Token 没有转账检查点，不能靠前端更新改成此模式。只有新 release 通过 `buildContinuous` 部署的 Token/分配器启用此模式；旧部署保持旧行为。没有本轮重部署授权执行记录。

## 跨层交付范围

- 合约：累计器、Token 检查点、FeeVault 入账、Factory 初始化与绑定、领取接口。
- 索引/API：已赚未领、待兑换、待释放、历史到账/领取；展示不能成为结算依据。
- 前端：普通持有人一个领取入口，展示可领与待释放；新模式不展示 Root 请求和七天等待，旧测试 release 依据版本保留正确能力。
- 部署：新 runtime、ABI、manifest、权限矩阵、预检及正式环境保护；已有测试余额不得误接新账本。
- 文档：新的收益归属规则、管理员操作、用户帮助、测试矩阵；旧容量报告保留为旧模式证据。

## 必须通过的验收

| 场景 | 验收标准 |
|---|---|
| 买入前后、卖出前后、普通转账 | 不继承买入前已赚收益；转出不抹去旧收益 |
| 集中入账前买入 | 明确验证所选经济规则；持续模式不能瞬间取走完整一批 |
| 同交易借入并归还 | 持续模式没有时间流逝时不能获得该时段释放收益 |
| 追加资金、微额注入 | 已赚收益不变；旧承诺日程不被恶意无限延期 |
| 时间边界与长时间无人调用 | 有界追记，与独立数学模型一致 |
| 自转、零额转账、频繁 checkpoint | 不重复计奖、不通过舍入阻塞释放 |
| 零有效供应、全部卖出、首个买入 | 不向首个参与者追溯支付无人持有时段 |
| 系统地址与毕业库存移动 | 有效供应不包含协议库存，普通持有人收益不丢失 |
| Quote 原生币/ERC-20、兑换失败 | 资产隔离，失败不产生无担保可领额 |
| Creator tax 与可选股票质押 | 保持已冻结拆分，关闭质押不阻塞其他受益人 |
| 领取失败、恶意接收者、重入 | 原子回滚，不影响其他用户偿付能力 |
| 随机操作与累计守恒 | 支付+未支付负债不超过真实资金；独立模型对照 |
| Gas 与状态增长 | 单次转账不随持有人总数或市场历史长度增长 |
| V4 回调、归集与转账交错 | 无递归死锁，无中间余额导致的错误分配 |

测试网验证与正式广播尚未执行；本文件记录已实现规则和后续验收要求，不是测试报告，也不代表生产就绪。
