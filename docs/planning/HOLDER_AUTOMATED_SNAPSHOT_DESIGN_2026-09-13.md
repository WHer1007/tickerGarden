# 自动化 Holder 快照：已确认范围与实施边界

日期：2026-09-13。状态：快照合约、批量归集和失败隔离已实现并通过本地回归；后台自动化先列入 TODO，暂不实施或启用。证明 API 与页面迁移尚未完成，未部署。

## 已确认的业务范围

- 将 Holder 从连续转账记账改为周期快照。
- 只计算钱包直接持有的 Meme 余额。不计算 LP、借贷、质押、跨链或其他外部协议中的间接权益；不实现 LP 适配器。
- Safe 等智能合约钱包可按直接余额参与，不能通过 `code.length == 0` 把智能钱包全部排除。已知协议库存地址继续排除。
- 未来收益按快照时的有效钱包余额占比分配，不再按整个期间的持有时长积分。快照之后卖出不取消已确定的该轮奖励；之后买入不继承旧用户该轮权益。
- 后端自动计算、核验、发布；由专门的普通钱包提交，不要求多签逐轮确认。
- 用户暂不提供发布地址，生产配置必须保留未配置状态；不得代填部署者、Treasury 或治理 Safe。开发测试使用测试账户。
- 奖励故障只影响奖励计算、发布或领取，不向 Meme 转账注入回调，也不永久停止代币交易。
- 保持现有手续费分配比例和 Quote／Meme 原资产支付，不重新引入兑换路由。

## 尚未确定的参数

- 结算周期：24 小时是建议值，用户尚未明确确认；不能将建议写成已批准生产参数。
- 随机时间：早前提出过随机发放以增加抢快照难度。需要区分随机取样区块与实际发布时刻；两者不是一回事。不得默认为每轮末区块而遗漏该要求。
- 发布钱包与权限轮换方式：公开地址后续提供；配置权限与逐轮自动发布权限分开。

## 建议实现边界

1. 代币保持普通 ERC20 余额更新，取消 Holder checkpoint 外部调用。历史部署的不可变代码无法原地改变，需要新 release。
2. 后端从经确认、完整索引的数据增量重建指定区块末余额，校验供应量、排除地址和链／市场身份。缺失历史时停止该市场该轮发布，不猜测余额。
3. 每个市场／轮次／资产独立绑定真实奖励预算；零新增奖励不发布空轮次，零有效余额不错误分给任意地址。
4. Root 及其证明绑定链、分配合约、市场、轮次、用户和金额。每轮生效后不可随意改写，用户领取状态防重放，预算不能被其他轮次重复占用。
5. 支持一笔交易批量提交多个市场的 Root，批量大小以实际 Gas 测量确定；调度限流、失败隔离和重试不能重新随机抽样或重复发布。
6. 钱包领取从数据库读取证明，交易模拟与发送才使用钱包链路；前端不得扫描 RPC 重建余额或名单。
7. 普通发布钱包不拥有协议管理或 Stock 本金提款权限。但其恶意 Root 仍可能重定向被授权的 Holder 奖励，独立复算与预算上限不能被描述成无需信任证明。
8. 领取 proof 必须持久保存，并公开可核验的完整名单与输入摘要。后台停止时，已发布权益不应因证明仅存在于临时内存而无法领取。

- [ ] **持久状态与并发控制**：保存“待处理 → 数据及预算固定 → 归集待确认 → 资金确认 → Root 待确认 → 已开放领取”。增加任务唯一键、工作租约、钱包 nonce 协调、交易哈希和重启恢复；交易状态不明时先核实，不盲目重发。
- [ ] **到账确认与预算核对**：根据 receipt、确认状态及 Distributor 链上可分配账目确认资金，处理重组。发布预算不能超出实际未分配金额，不能再次占用旧轮次预算；没有资金的空轮次不发布。

- [ ] **数据和证明持久化**：在发布前保存完整输入、分配清单、Merkle proofs、生成规则版本与摘要，保证可独立复核及恢复；不能只保存在 worker 内存中。
- [ ] **证明 API 与领取页面联调**：前端从后端数据库读取证明和状态，钱包链路负责模拟与发送领取交易；不得让前端扫描 RPC 重建名单。区分资金未到账、Root 未确认、可领取及已领取。
- [ ] **监控与故障恢复**：监控队列积压、归集失败、偿付缺口、发布权限变化、重复轮次、重组、nonce 和 Gas 预算；对异常市场限流隔离，保留日志与人工恢复入口。
- [ ] **验收**：覆盖千／万市场队列、仅部分活跃市场、重复事件、交易超时、进程重启、并发 worker、部分归集失败、Gas 中断、归集后未发布、Root 已发布但响应丢失、数据不一致和链重组。验证不重复转移、不重复分配、不丢证明、不向交易路径加入奖励依赖。

## 当前仓库复用结论

当前 `tools/holder-rewards/worker.mjs` 是受限于测试 release 的连续奖励归集 worker，不是快照 Root 发布器。现有重试、签名前模拟和交易日志思路可参考，但不能直接启用生产快照。

Holder Distributor、Token、FeeVault 领取接口、Factory／部署构建、ABI／权限表已按快照合约调整；索引与证明 API、领取页面及文案仍需后续跨层迁移。历史连续收益测试可作为历史行为证据，不能用其通过宣称快照功能完成。

任何新增自动发布功能都必须在用户管理的签名环境运行；本轮未读取、索取或生成生产私钥，未创建定时广播任务，未部署。
