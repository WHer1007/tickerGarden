# 当前报价存储改造

## 行为

- 每个环境、链、部署、资产、来源只保留一条当前有效报价/状态；主网现有单来源配置约 196 条，数量不随运行天数增长。
- 继续统一每 5 分钟刷新。USDG 固定为 1 美元，只覆盖同一条记录，不调用外部报价。
- 当前查询只读取小表，不再从历史中扫描、排序选最新。详情、Explore、Stats 保持共用价格入口。
- 短暂抓取失败不覆盖尚未过期的成功报价；报价有效性仍由后端判断。过期边界保持原规则，不新增前端过期判断。
- observed_at 记录最新已处理抓取时间，防止并发或延迟响应覆盖更新结果；成功价格自身的 as_of 不倒退。
- 每次观察（含失败、重复或晚到响应）输出 price_reference JSON 日志，包含环境、部署、资产、来源、时间、报价和状态，不包含凭据。

## 迁移与上线顺序

本记录描述代码与迁移方案，不代表已在测试/生产执行。

1. 先在测试环境验收。暂停该环境价格刷新调度并等待在途刷新结束；停用旧 Pipeline 的价格写入入口，避免旧版本 ON CONFLICT DO NOTHING 导致报价不再更新。
2. 备份数据库。在已加载对应环境迁移配置的进程中运行：
   `node --experimental-strip-types services/backend-ts/scripts/export-price-history.ts /secure-log-path/prices-before-0028.ndjson.gz`
   脚本只读、流式压缩导出历史，拒绝覆盖文件，文件权限 0600。记录完成行数，用 gzip 完整性检查及逐行 JSON 校验验收导出。
3. 执行标准迁移命令应用 `0028_current_prices` 及后续 `0029_price_batches`。迁移在事务内取得表锁，保留每组最新有效记录及最新观察时间，重建主键、回填并更新统计。TRUNCATE 释放旧表及索引空间；失败时整体回滚。不更改资金账本、成交和奖励数据。
4. 现有 Pipeline 已有价格表 SELECT/INSERT/UPDATE，Read API 仍只读。`0029` 新增批次表，需要重新执行已更新的标准权限脚本并验收。
5. 发布新的 Pipeline、读接口及 Worker，再恢复价格调度。迁移前不要运行新的写入代码。Vercel 仍按 test/master 来源及 sin1 发布门槛执行。
6. 验证连续两轮刷新后总行数稳定、observed_at 前进、USDG=1、历史日志已记录，详情/Explore/Stats 正常。

新鲜失败的观察只保留在日志，数据库保留的可能是尚未过期的上一次有效值，这是为了避免临时失败清空统计。它不是历史记录集合。

## 回退和日志保留

旧版写入端不能直接回退启用；旧查询可读取新表，但旧 INSERT 会忽略相同资产/来源。需要保持新写入端，或暂停刷新并通过数据库备份恢复旧表结构后再回退。

运行时日志进入现有进程标准输出／Vercel 日志，不能视为永久归档。外部 CLS 等日志接收服务尚未在本次改造中启用；存储平台保留期决定可检索的历史跨度。迁移导出的压缩日志独立保管。

## 本地验证

- 后端完整门槛（生成物、打包检查、契约、类型、单元测试）：230 项测试通过。
- 真实 PostgreSQL 相关集成测试：10 项通过、0 跳过，覆盖当前报价存储、迁移、详情、Explore、Stats 和后台展示。
- 并发／乱序、重复观察、失败保留有效报价、过期边界、跨部署隔离、100 次写入行数不增长均已覆盖；批次失败整体回滚。
- 旧表 20,001 条记录迁移后只保留对应资产的一条有效记录，重复迁移不再执行。
- 导出脚本本地导出 2,001 条记录，gzip 完整性、逐行 JSON、文件 0600 权限和拒绝覆盖已有文件验证通过。
