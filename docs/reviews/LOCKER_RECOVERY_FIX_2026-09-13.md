# Locker 外来余额隔离与费用补缺口修复

用户于本任务批准两项修复。修改对象为当前工作区候选，未部署、未广播，既有不可变部署不会自动获得修复。

## 改动

- `LaunchLockerCompounding` 在归集后、发送复投资金前，通过单独的 PositionManager 调用原子执行两币种 SWEEP。收到的外来余额增加隔离账目，不增加费用账目。清理和复投同属一笔受重入保护的交易；native 预算仅在后续增加流动性调用中发送。
- `_collect` 不再因已有缺口提前回滚；始终保留历史隔离余额，仅把新观察到的盈余加入隔离账目。新收费用按币种先修复缺口，仅超出缺口部分增加费用账目。历史费用账目也不做隐式减记。
- 复投前后继续检查两种资产的覆盖率。归集未补足时只能独立归集，不能复投；失败复投会回滚其内部归集、外来余额清理、授权和 LP 操作。
- NFT、池、区间、所有权、流动性增量、投入上限、Keeper、期限及授权归零约束保持。ABI/事件签名未新增；`LockedFeesCollected` 与归集返回值仍表示实际收取总额，含补足部分。

逐资产规则：`D=max(I+F-B,0)`，收取 `C` 后 `F'=F+max(C-D,0)`。已建立的隔离下限 `I` 不降低。若不足额，剩余缺口为 `D-C`；若补足，超出部分才增加未来可支出费用。PositionManager 外来余额同时增加 `B` 与 `I`，不能冒充 LP 费用或抹去已有缺口。

## 剩余边界

当前池LP费为零，复投不会凭空产生收益；后台自动触发仍未启用。外部资产自身持续扣减、冻结、异常回调仍可能令操作失败，本次解决的是正常可转账资产下的外来余额干扰和已有缺口恢复。公开归集只能收取实际产生的LP费用，不能保证未来一定有足够费用补足。

Locker creation bytecode发生变化，新发布必须重新生成依赖它的CREATE2地址和部署身份。历史release证据保持原样，不能复用为新候选的部署证明。
