# 第二阶段容量优化实施与测试报告

日期：2026-09-14（北京时间）

状态：**本地限定范围验收通过（LOCAL_SCOPED_ACCEPTANCE_PASSED）**。代码仍在当前工作区，未提交、未部署。生产准备状态为 **NOT_PRODUCTION_READY**；未启用周期 Holder 签名发布。

## 本次实现

1. **增量统计**：新增分钟、小时、天级精确整数时间桶，整桶走汇总、边界区间读取原始 rollup。交易修改/删除、区块失去 canonical/finalized 时同步反向调整；并发最终化与交易写入通过区块共享锁串行。
2. **增量发布**：完整检查点后只写变动市场，摘要绑定父修订、父摘要、变动记录、人口数量、算法和覆盖证据。每条增量链有 256 层上限，正常投影在到达上限前生成新完整检查点；增加独立全量审计 CLI。
3. **持久任务列表**：创建事件目录、市场观察工作列表、Holder 工作列表入库。重试只加载未完成项；SQL 筛选待观察市场，避免每块向应用传回全部历史市场 JSON。保留全人口计数和最终性/覆盖校验。
4. **按时间刷新 Staking**：核对待激活量与 32 个激活槽，记录下一次激活时间；到期、相关事件、观察版本不匹配时重新读取。调度无法核对时保守重读。排除零 ABI 值触发全部原生币报价市场刷新的误判。
5. **Holder 统计引用计数**：正余额账户、资产分组及排除地址建立精确派生计数；跨零和排除列表变化同步维护。共用排除地址按语句汇总，避免每市场逐行更新形成长版本链。
6. **跨实例结果缓存**：展示统计绑定源写入版本、generation、canonical/finalized 锚点，事务内失效；最多 128 项/部署、15 秒 TTL、单项上限 4 MB。缓存不参与领取、授权或签名。
7. **推送合并**：保留每条原始日志，同块、相同 removed/head 的日志封装为至多 256 条的持久批次。重启重试沿用同一幂等键；下游仍独立读取完整日志区间。历史池路由发现只扫描生命周期事件。
8. **重建和清理**：派生数据重建在同一个原子事务内分批删除，控制单条 SQL 时间；清理过期工作列表和旧 generation 的调度数据。

新增数据库迁移 **0006–0011**。Read API 新增 DML 权限仅限可丢弃的 `statistics_result_cache`；资金相关源表权限边界保持。Creator 交接、紧急退出、LP 复投说明与手动 Holder 签名的既有产品边界保持。本阶段 70 个合约源码文件与上一阶段证据一致，未改变合约或 ABI。

## 数据与方法

使用本机 M2 / 8 GB、Node 24、PostgreSQL，顺序执行数据库 DDL、容量和 Relay 测试。构造 **20,000 个未毕业 + 1,500 个已毕业市场**；正常生产投影代码读取 ABI 日志和确定性的双 RPC 模拟返回，初始仍核对 1,075,000 次模拟合约读取。另行装载 215,000 条交易读模型。

随后重放 43,000 条基础 Transfer 和 2 条增量 Transfer。最终保留 86,002 条 ABI 日志、21,502 个市场版本、43,000 条余额、21,500 个 Holder 快照。每市场总供应量均精确等于 10²⁷；迁移后排除地址引用计数与完整源数据对比的差异为 0。

这是本地合成数据验收。未在 RH 创建这些链上市场，没有使用真实 RPC 配额，没有广播签名交易。Relay 的 WSS/RPC/队列服务为本地模拟；两个 Read API 为独立进程及连接池，但位于同一台机器。

Relay 在本轮每组 100 条同块事件测试中只发送 **4 次队列通知**，全部原始事件保留。100 条/秒持续 10 秒的 1,000 条输入全部由已投递批次覆盖，无 dead 记录；通过重复日志、removed 日志、队列 503、断线补日志、同块漏推、数据库连接终止及进程重启测试。队列返回成功不等价于链事件已经完成资金结算。

## 本轮发现与修复的回退

- 按市场 advisory lock 导致首次全量发布耗尽锁表：改为每部署一把锁，21,500 市场重跑通过。
- 新汇总表没有 ANALYZE 时触发高代价嵌套循环：在全局统计事务内限制此计划。在无 ANALYZE 副本上，默认路径稳定超时，修复路径约 **440 ms**。没有提高 5 秒 SQL 时限。
- 一次删除全部 Holder 派生行触发 SQL 超时：改为原子事务内分批删除，保留重建一致性。
- 排除地址逐行计数造成首次余额重放回退到约 **128 秒**：改成语句级聚合后，同库 43,001 条余额效果重放约 **13.9 秒**，供应量和引用计数仍全部对齐。
- 全零 ABI 字段可能误判为原生币地址变化：已排除无效零标识并增加回归测试。

**仍有写入代价**：新增精确计数后，首次余额重放约 13.9 秒，高于第一阶段约 5.4 秒；它换取常用统计读取减负。首次余额重放与首次 Holder rewards 投影是不同任务，不能混用两项耗时。后续更大账户规模应继续测量计数写入及重建成本。

`capacity.json` 保留了冷统计修复前的原始 `pass:false`，其中唯一失败项为小时统计的 5 次 503；没有改写成成功。该项由 `cold-statistics-retest.json`、`daily-read-retest.json` 及清空结果缓存后的 `daily-stats-load.json` 替代验收。其他失败及中间结果保留，包含锁表耗尽、测试夹具修正和重放回退。

## 运行边界与后续容量门槛

- 未提交或部署，未启用周期 Holder 发布；迁移只应用于已清理的本地测试 schema。上线前应在备份副本预演存量回填及源表锁时间。
- 尚未验证 50k/100k 市场、更大 Holder/持仓人口、百万级以上历史增长、跨主机竞争、真实 RPC 限额、Vercel 冷启动或 24/72 小时持续负载。
- 全人口计数、部分完整检查点和 Holder 覆盖推进仍有 O(N) 工作；本轮没有声称全部路径变为常数开销。共享 Stock/Quote 或全局配置事件采用保守观察范围，批量重算与真实 RPC 预算仍需专项容量验收。
- 无筛选的全市场统计接口仍返回较大结果；本轮中位约 1.65 秒。前端常规查询继续按可见市场和组件发起。
- 第一阶段本机 PostgreSQL 并发 DDL PANIC 根因尚未得到独立结论；本轮采用串行 DDL，不能以本轮通过推断引擎问题已消失。
