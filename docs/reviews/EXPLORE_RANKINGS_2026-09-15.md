# Explore 排名改进验收 — 2026-09-15

范围：展示层排名、分页及更新交互；未修改合约、交易授权或结算。发布目标为 test / Robinhood Testnet 46630。

## 实现

- Recent buys：`market_latest_buys` 每个项目一行，在已确认交易写入事务内增量更新；B-tree 直接读取最新位置。内部兑换、零额交易不参与，重复及较旧事件不顶替新事件；撤销、分类变化和 canonical/finalized 变化会修正受影响项目。
- Market cap：UTC 20 分钟桶共享排名，后台原子发布。游标固定排名版本，详情读取当前 finalized publication，及时过滤阶段变化。构建失败保留旧榜，成功后清理两小时前的快照。
- Pipeline 复用现有 `/internal/dispatch` 每分钟调用与价格刷新入口。锁和时间桶避免重复构建，不新增服务、签名器或链上操作。
- 前端仅在 Recent buys 激活且页面可见时，最多每 2 秒查询首页变化；交互中和后续页面不自动跳动，提供 Show latest。市值排名版本每 30 秒探测，卡片数值独立更新。Stock 筛选作用于两阶段。
- Read API 对新表只有 SELECT 权限；相同在途目录请求合并并限制并发；请求阶段不再按项目检索交易历史或重新计算全榜。

Recent buys 是实时活动列表，只显示已有符合条件买入的项目；未浏览项目可因新买入移到游标前，不保证一次翻页完整覆盖全目录。完整目录可使用 Newest/Oldest/Market cap。

## 验证

- 前端 454 项测试、构建通过；路由/应用/历史浏览器生命周期通过。
- 后端 86 项测试、构建通过；24 项 PostgreSQL 集成测试通过，无跳过。
- 排名集成覆盖重复及乱序事件、内部兑换、链回退、旧排名游标、数值缺失、生成失败回滚、当前阶段、生产 temporal storage 分支和权限。
- 真实 Hono + 独立 PostgreSQL + 120 个合成市场，桌面/390px 移动端通过：买入置顶、悬停保护、后续页冻结、Stock 双阶段筛选、稳定市值分页、Bloom 变化、缺失数据提示及配置复用。

## 本机数据库规模基准

| 项目数 / 历史买入 | 市值榜生成 | Recent buys 第 100 页 | Market cap 第 100 页 | Stock 筛选 P95（Recent / Cap） |
| --- | --- | --- | --- | --- |
| 20,000 / 400,000 | 976 ms | 1.79 ms | 2.05 ms | 29.23 / 1.23 ms |
| 50,000 / 1,000,000 | 1,514 ms | 2.84 ms | 2.15 ms | 39.38 / 1.37 ms |

两档规模均连续翻阅 100 页无重复；两种排序的 16/64 并发请求全部成功。50,000 档的 64 并发 P95 为 Recent 15.69 ms / Cap 19.70 ms。该数值包含本地连接池排队，不含公网、Vercel 或真实链上摄取成本；不是生产 SLA。

首次压测暴露联合视图的 domain/text 条件阻碍索引下推。修正后按当前 publication 的实际存储类型直接索引读取项目；查询计划为排名索引 + 项目主键查询，不扫描交易历史。20,000 档复用了之前生成的合成历史数据，修正代码后重新测量；50,000 档追加到 1,000,000 笔后测量。
