# 共享报价批次与数据库耗时

代码及本地验收记录；尚未部署到测试或生产。

## 价格读取

- `0029_price_batches` 每个环境／链／部署保留一个版本号。它只存当前版本，不存历史价格。
- 价格行覆盖写入、版本递增和 PostgreSQL 通知在同一条事务语句内完成。失败或旧观察没有改变数据库时，不发布虚假的新批次。
- 同一轮详情和 Stats 更新显式传递同一个 `PriceBatch`，使用相同数据和估值时间。Explore 卡片来自详情物化结果，排名读取卡片，不另取价格；兼容排名任务与新创建详情使用相同批次读取模块。
- 展示 Worker 的扫描与维护循环共享一个 `SharedPriceReader`；Pipeline 的新创建详情、价格刷新和兼容排名也共享各自进程的 reader。独立进程不共享内存，但读取同一个数据库版本，并非声称所有实例合计只执行一次 SQL。
- 收到价格通知立即失效；断线重连也失效。丢通知时，按需每 5 秒核对一次版本（并非每 5 秒重新抓取外部价格）。版本不变时只返回版本号，不聚合／传输全部价格。
- 每轮按当前后台时间重新判断有效性，不因内存复用延长有效期。并发请求合并，旧的在途响应不能覆盖新缓存；数据库读取失败仍向任务报错，不静默使用失败缓存。
- 展示维护先检查待处理市场，没有工作时不读取价格。价格通知也触发 Stats 更新，不等待原有 60 秒定时兜底。
- 浏览器和页面访问流程未改变；不增加页面组件，不改变外部价格五分钟刷新周期、二十分钟排名周期及资金结算规则。

## 耗时与计数

`createDatabasePool` 统一记录，保留 pg 的 Promise 和 callback 接口。

| 字段 | 含义 |
|---|---|
| connectionWaitMs | 等待连接池分配及新连接建立的耗时 |
| sqlMs | 取得连接之后，驱动发起查询至返回／失败的往返耗时；包含驱动排队、网络和数据库执行，不等同于 PostgreSQL 服务器纯执行时间 |
| taskMs | 整个任务的墙钟经过时间，使用单调时钟测量，包括 RPC／CPU／其他等待 |
| queryCount | 完成或失败的 SQL 次数 |
| slowQueryCount | SQL 往返达到 500ms 的次数 |
| sqlTimeoutCount | 语句／锁／驱动读取超时次数；不把显式取消和 NOWAIT 锁竞争当超时 |
| connectionTimeoutCount | 连接获取超时次数，与 SQL 超时分开 |

- 连接获取达到 200ms 发出 `database_slow_connection`；慢 SQL 发出 `database_slow_query`；两类超时分别发出 `database_connection_timeout`、`database_query_timeout`。
- `database_task` 记录任务结果及上述拆分值，覆盖 display.advance、display.prepare、stats.publish、explore.rank、prices.refresh、launch.prepare。
- taskMs 是完整经过时间；并行 SQL 的 sqlMs 是各调用之和，不应以 taskMs 减 sqlMs 推导 CPU。嵌套任务的 SQL 归属于最内层任务，避免累计重复；外层 taskMs 包含子任务时间，不能再相加作为总墙钟时间。
- 每次调用在告警去重前独立累计。慢事件只含 SQL 哈希、耗时与任务名称，不输出 SQL 文本、绑定值、数据库 URL 或凭据。
- Pipeline 已有鉴权 `/internal/metrics` 增加 `databaseTimings`；展示 Worker 本机 `/healthz` 增加 `database`。这些是进程生命周期计数，重启重置；Vercel 每实例独立，不能当全站累计。需要全站统计时按任务日志聚合，不能同时累加任务日志与对应单条慢查询事件。
- 接收平台可对任意超时触发告警，对慢 SQL 比例、任务耗时分位数设置阈值。本次未新增付费服务、CLS/Sentry/Lark 账号或外部通知配置。

## 上线顺序

与尚未发布的 `0028_current_prices` 一起上线：先按当前报价存储说明导出历史并暂停价格写入，再执行 `0028`、`0029` 和标准权限脚本，更新 Worker／Pipeline／读服务，恢复刷新。`price_batches` 的 Read API 只读权限与 Pipeline 读写权限已加入标准权限清单。

上线后核对：两轮刷新版本递增但价格行数不增长；数据库通知正常；同一报价版本只重新读取一次全量价格；模拟断开通知可低频恢复；统计与价格来源一致。检验慢查询及超时告警应在隔离测试库执行，不能对生产故意制造超时。

## 验证结果

- 后端完整门槛通过：生成物、打包、接口契约、类型检查及 239 项单元测试。
- 完整数据库集成：52 项通过，0 失败；1 项默认关闭的 100,001 Holder 合成容量压测未运行。
- 批次测试覆盖：三消费者一次读取、并发合并、提交通知、失败不递增版本、旧观察不递增版本、不同部署隔离、漏通知恢复、过期边界、旧在途结果不能覆盖新缓存、无工作时不读取报价。
- 数据库埋点验证 Promise/callback 两类接口；本地 max=1 的连接占用测试测得约 121ms 连接等待、约 0.6ms SQL，互不混算。750ms 获取连接超时和 20ms PostgreSQL 语句超时分别累计，错误对象及后续连接可用性保持原样。
- 显式取消、NOWAIT 竞争不会被误计为 SQL 超时；嵌套和并发任务各自统计；日志写入失败不改变业务结果。
- 读写及监听复用已有数据库连接，不新增连接池预算。
