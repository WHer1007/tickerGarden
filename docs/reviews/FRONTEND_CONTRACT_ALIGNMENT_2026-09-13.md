# 前端与最新版合约对齐

2026-09-13。以下记录最初本地适配阶段；随后已完成新版本测试站切换和 Vercel Preview 发布，见 [发布验收](FRONTEND_LATEST_RH_RELEASE_2026-09-13.md)。

## 功能与交互

- 新增独立的钱包快照奖励路径：按已审查 release catalog 的链及 Hook 匹配，只读取后端轮次/证明接口；不以旧合约接口调用失败作为版本判定。
- 展示轮次、快照区块和两类可领原资产，支持分页。待归集、待发布、发布者未配置、无符合条件轮次、接口错误分别展示；后端缺数据不变成零奖励。
- Holder 调用新版 Distributor 的 `claimSnapshot`，不走 FeeVault Creator/Staker 领取入口。前端检查域、链、合约、市场、账户、轮次、金额和 Merkle 证明；钱包操作时再核对链上绑定、模式、Root、剩余预算和领取位图。
- 领取弹窗只提供仍可领的资产，原资产直接到账；已领取一种资产后保留另一种。确认回执后暂存领取位图，直到数据库追上对应区块，再交回 finalized 数据（含重组后的状态）。
- 切换钱包/市场使旧请求失效；分页和刷新只更新奖励区。确认弹窗开启时暂停周期奖励刷新。
- 快照领取使用独立的上线开关，不能借用旧连续奖励版本的批准。现有旧市场接口保留并明确显示旧分配模式。
- Creator/Stake 去除自动兑换暗示，Creator “Receive in” 展示 Quote / Meme；Stock 本金缺口导致存款失败时给出明确提示。

## 文案与 Docs

- 首页、Create、Stake、Claim、Docs、Terms 和 Risks 对齐钱包余额快照、原资产领取和外部资产风险。
- Holder 分享的是 Creator 基础手续费份额的 50%，不包含 Creator tax；修正 Create 动态文案覆盖静态文案的问题。
- Holder 说明拆分资格、领取时间和到账资产：仅直接钱包余额，LP 不计入；快照后卖出不删除该轮权益；无固定合约发放周期。
- Stake 的最低值是所选市场的总仓位要求，追加可以低于最低值，其他市场仓位不合并计算；0.5 是当前规划配置而非不可修改常量。Stake 的 30 秒生效等待、24 小时锁定与 Holder 快照周期分开描述。
- 正常退出与应急退出区分；Creator 费用权利两步交接只影响未来费用，旧版本权益保留。Docs 明确使用经验证的合约入口进行费用权利交接，并未声称此页面新增了完整治理界面。
- 说明 Staker 极少数记账失败时该笔新奖励放弃、交易继续、后续仍可正常分配。
- 去除统计固定等待 10–20 分钟的承诺；旧市场版本差异集中到独立帮助条目。
- 本地启动工具识别钱包快照源码，不再强求已移除的 Holder stream clock；仍保留原 Stake/Unpause 时钟、链及部署配置核对。
