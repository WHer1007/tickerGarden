# Explore 展示数据链路对齐

日期：2026-09-18。范围：本地 `test` 分支代码与隔离测试，未发布测试或生产。

## 已完成

- Explore 独立 bootstrap，不请求全局 health，不要求 finalized publication，不受全局快照轮询或断网清空逻辑影响。
- 列表、可见卡片统一读取 confirmed display 的数据库字段；创建回执已核验但 Worker 尚未追上的记录直接进入列表。Growing / Bloomed 使用相同数据源。
- Worker 保存当前美元市值、24h 成交额估算、Bloom 原始进度及最近有效买入位置。美元值复用共享报价，无额外 HTTP/RPC 报价请求。无交易的成交额为 0，缺少覆盖或报价为 null。
- 前端不再按 20 分钟有效期拒绝/清空数据。20 分钟仅用于后台市值排名，卡片数值独立更新。
- Recent buys 按区块/交易/日志位置排序，最新有效买入在前，过滤内部及零额交易；最近买入位置独立保存，不随 24h 缓冲淘汰。
- 复用同一数据库通知入口的 SSE，150ms 合并变化通知，仅查询受影响的可见卡片；列表变化校对第一页。60s 断线补漏，重连补读；后台标签页停止流，返回后恢复。
- 保留 Newest、Oldest、Market cap、Recent buys、Stock 筛选和搜索。分页游标签名绑定筛选与排序，市值分页固定排名版本，409 可恢复第一页。
- 重组撤销展示状态，并校验尚未进入 Worker 的最近创建记录（每轮最多 32 个项目创建区块，5s 校验间隔限制），撤销与通知一起提交。
- 存储独立的小型卡片列，目录不展开 Holder/成交/图表大 JSON；查询合并和读容量限制继续生效。移除会诱导市值查询退化为平方复杂度的冗余索引。
- 未增加页面组件或说明文案；有数据库图标时直接使用，不再等待元数据下载。

## 验证

- Web 完整测试：544 项通过。
- Backend 完整单元测试：160 项通过；HTTP/契约检查：12 项通过。
- PostgreSQL 隔离数据库：权限/队列/Explore 三项集成测试通过。覆盖无最终快照、空列表、旧时间戳保留、筛选游标绑定、排名版本、卡片新值、创建记录切换、重组撤销/恢复。
- 浏览器执行实际应用，所有外网请求拦截：无需 health/RPC；单个通知只查询对应卡片；Bloom 进度变化；新项目加入；重组移除；断网保留；只有一条展示流。
- Web 构建、资源预算、SEO 检查通过。
- 本地 20,003 条展示记录，未依赖手工 ANALYZE：Newest 27ms、Oldest 22ms、Recent buys 30ms、Market cap 524ms、50 张卡片 8ms。属于本机合成数据验证，不能等同线上延迟或完整吞吐承诺。

## 发布依赖与边界

先应用 `0020_explore_display` 和角色权限，再发布 Read API/展示 Worker，确认 Worker 填充卡片统计和初始排名后发布 Web。原目录接口保留兼容其他业务；奖励结算和资金确认规则未改变。没有执行线上迁移、发布或钱包交易。

24h USD 成交额为配对资产成交量乘共享当前美元价的展示估算，不是逐笔成交时美元价的历史加总。新市场尚未进入市值排名快照时先置于既有榜单之前，下一周期统一排名；数值不受此周期限制。Recent buys 是动态事件顺序，持续交易期间不承诺游标遍历覆盖所有项目。
