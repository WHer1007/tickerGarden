日期：2026-09-06。范围：TickerGarden 当前 V1 合约及前端；测试网络 421614，最终生产目标 RH 4663。
更新：接收器 P0 阻塞已在 R2 修复，执行者、ETH quote、测试基线和模板已激活，见 [R2 修复记录](ARBITRUM_RECEIVER_FIX_R2.md)。以下“当前状态”保留制定方案时的问题背景；后续用例以新部署清单为准。

## 1. 当前状态与必须先解决的问题

- 核心已部署、尚未完成 quote/baseline/template 激活；部署证据见 `deployments/manifests/arbitrum-sepolia-421614.v1.deployed.json`。
- **原部署 P0（R2 已修复）：内部兑换执行权限不可操作。** 链上 FeeVault 的 `settlementOperator()` 当前为 `0xD84897cD860Da0B51D39a252961B18D54fBbb266`。该接收器只有 receive/withdraw，不能调用 `setSettlementOperator` 或执行兑换；后者要求调用者是接收器自身。持有人、创建者、质押者的内部兑换不能因此认定可用。此前部署校验验证了地址与字节码，遗漏了这个权限可调用性检查。
- 推荐修复：接收器增加仅 owner 可调用、明确目标 FeeVault 的执行者配置能力，并验证非 owner 拒绝。由于现有接收器不可升级、FeeVault 平台接收方不可变，应使用新 release 重新部署关联核心图，再更新前端与索引清单。不能只更换前端地址、给 EOA 另授 AccessManager 角色或用 vm.prank 冒充接收器来宣称公开链已修复。
- 4.2 ETH 毕业门槛尚需测试资金。上次余额约 0.099 ETH，只适合小额冒烟，不能支撑原参数的毕业链路。
- 链上只读确认：持有人 epoch 为 2,592,000 秒（30 天），finality 等待 600 秒，root review 为 3,600 秒；原币奖励退出等待 604,800 秒（7 天）。公开链不可 vm.warp/vm.deal。

第一道通过条件：新部署中 owner 能真实配置独立 settlement operator，operator 能正常结算，非 operator 被拒绝；核验 complete、全部代码哈希、关键依赖、角色及配置后才激活业务。

## 2. 三种测试环境分别证明什么

| 环境 | 主要用途 | 不能替代的事项 |
|---|---|---|
| 本地单元/不变量测试 | 舍入、权限、异常代币、重入、故障注入、重复执行、边界时间 | 不证明公开链服务可用 |
| 固定区块 Arbitrum/RH Fork | 真实 v4 外部依赖；RH 真股票身份与质押；时间快进 | 本地合约和合成 TWAB 不等于公开部署/真实持有人根 |
| Arbitrum Sepolia 实际部署 | 钱包签名、真实收据、服务结算、真实索引与页面、公开链时钟 | 模拟股票不证明 RH 真股票；缩小经济参数不证明 4.2 ETH 原参数 |

保持 RH 真股票 Fork 独立验收。禁止直接复制 RH 股票地址、白名单、Merkle root 或市场 ID 到 Arbitrum。

## 3. 准备与资金

1. 建立测试运行编号，锁定 commit/dirty diff 哈希、chainId、部署清单、基线/quote/template ID、代码哈希、起始区块及经济参数。
2. 管理账户继续用现有测试钱包；另设创建者、交易者 A/B、质押者 A/B、无权限用户和结算服务账户。不得全用一个账户测试权限或收益归属。私钥不写入用例、日志或仓库。
3. 明确命名并部署仅测试用 baseline fixture，注册其真实本链代码哈希；不得冒称官方 Pons 工厂。先配置 native ETH，再配置模拟股票身份、fingerprint 和 canonical vault。
4. 启用独立链的 Indexer/API/前端与数据库；从新部署起始块回放。核验页面 chainId、Factory/Router、quote/template、奖励服务和根生成器均指向同一部署。
5. 资金分档：小额创建/买卖冒烟先使用现有余额，并执行每笔预估；原 4.2 ETH 毕业测试建议另筹约 5–6 测试 ETH 作为单个市场的初始预算，实际按净募集、基础费、Creator tax、Gas 与后续交易金额计算。多市场须单独核算，不能假定 LP 中资金可立即取回循环使用。
6. 可另提低门槛测试模板以节省测试币，但需先确认模板/基线校验允许、保持相关经济参数一致并显著标注；不得覆盖原模板，也不得把它计为原 4.2 ETH 验收。
7. 根请求当前需 0.001 测试 ETH 服务费，另算 Gas。交易者与服务账户各保留余量；费用预算不与毕业募集资金混合。

## 4. 市场样本矩阵

核心矩阵：质押开/关 × 持有人分配开/关 × Creator tax 0/500 bps，共 8 种配置。
另补一个 250 bps 正常样本及 501 bps 拒绝样本。每种有效配置至少创建、原子买入、普通买卖和费用对账一次。

预算有限时先做两条完整主线：
- A：关闭质押，开启持有人分配，Creator tax 500 bps。
- B：开启质押，开启持有人分配，Creator tax 0；分别覆盖无有效质押和有有效质押。

其余组合先在 Fork 完整运行；公开链未执行的配置逐项标 NOT_RUN，不能合并为全部通过。

## 5. 分阶段操作与验收

| 编号 | 操作 | 通过标准 |
|---|---|---|
| P0-01 | 修复接收器、重部署、配置结算执行者 | 真实交易配置成功；越权拒绝；operator 能发起转换；绑定和角色可从链上重建 |
| P0-02 | 注册基线、ETH quote、启动模板 | ID/状态/经济参数一致；未激活、暂停、过期或身份漂移按合约规则被拒绝 |
| C-01 | 不启用股票质押创建市场 | 无需股票对象；market/gauge/stock 字段符合关闭状态；不能向该市场质押 |
| C-02 | 启用质押创建市场 | 有效股票和 canonical vault 才可创建；缺失/无效/暂停对象失败 |
| C-03 | 通过 LaunchAndBuyRouter 创建并 Developer buy | 一笔交易创建并购入，接收账户与余额准确；买入失败时整笔业务状态回滚，无残留市场 |
| C-04 | 创建表单与元数据 | 开关、税率上限、Website、图片上传状态、预览与最终 tokenURI 一致；如果 IPFS 尚未实现，标 BLOCKED，不以本地预览代替持久化 |
| T-01 | 曲线买入、卖出、多账户连续交易 | quote、最小输出、实际到账及储备一致；ETH 余额核算扣除用户 Gas；事件中的 feeAsset 与实际资产流一致 |
| T-02 | 余额/授权不足、过期、滑点失败、极小金额 | 正确拒绝，业务本金/状态不变；失败链上交易仍可能消耗 Gas；单独先做的 approve 不因后续失败而撤销 |
| F-01 | 每笔买卖费用独立对账 | 基础费和 Creator tax 分别记账；所有分配加总守恒；舍入余数符合源码；没有未实现的卖出销毁 |
| G-01 | 接近门槛、精确触发、跨越毕业门槛 | 按合约净募集口径核算；页面进度不以含手续费累计转入替代；边界金额由整数报价求解 |
| G-02 | 毕业执行与重试 | v4 pool、Hook、Executor、LP/locker 绑定正确；只能成功毕业一次；失败重试不重复铸造或转移资产 |
| T-03 | 毕业后双向交易 | 通过真实本链 v4 路由买卖；报价、滑点、价格、余额与费用一致；旧曲线入口按状态规则退出 |
| S-01 | 用户直接选择市场质押股票 | 首次标准 ERC-20 approve 后可 stake；页面不要求手动 Vault 分配；allowance 不足给出正确提示 |
| S-02 | 增加质押、多人不同时间进入 | principal、allocated、rewardEligible 与奖励累计一致；后来者不能领取加入前奖励 |
| S-03 | 正常退出、锁定期提前退出、rageQuit | 按当前合约规则释放本金/保留或放弃奖励；测试待结算状态下重复退出和重新进入；不能重复领回本金 |
| R-01 | 创建者/质押者内部兑换 | 批次真实兑换后 quote 入账，用户领取；无手动领取 meme 再卖出的常规流程；不能重复收取 Creator tax 或基础交易费用 |
| R-02 | 兑换失败、最低到账不足、重复批次 | 债务和资产守恒，失败不抹除用户权益；nonce/归属/额度正确；兑换服务恢复后能处理待结算项 |
| R-03 | 平台收益领取与接收器提款 | 只能流向固定平台接收合约，只有 owner 可提款；不影响用户债务 |
| H-01 | 持有人分配入账/转换/注资 | 只从创建者基础份额分出 50%；Creator tax 不参与；归属 epoch 不因晚结算改变 |
| H-02 | 真实持仓事件生成 TWAB 和根 | 包含转账、交易、排除系统账户、快照最终性；使用实际事件独立复算，不用单人合成叶子替代 |
| H-03 | 请求根、发布、审核、确认、领取 | 等待实际 epoch 结束与 finality/review；证明/账户/金额正确；重复、跨链、跨市场、跨 epoch proof 失败 |
| H-04 | 空周期、未结算费用、错误根、超时及结转 | 不得提前领取或重复分配；取消/过期/退款/服务费与剩余债务一致 |
| O-01 | 停止并恢复 Indexer/结算/根服务 | 重启回放无重复记账；链上交易成功而服务失败可恢复；重组由本地故障注入补测 |
| UI-01 | 首页、交易、市场、创建、统计、奖励 | 数字来自本链，未索引/待结算/可领取明确区分；钱包拒签、换账户、错链、刷新后交易恢复正确 |
| UI-02 | 移动端与连接钱包 | 核验实际支持的钱包、网络切换、授权和真实交易；不承诺未集成钱包通过；保持现有 V1 配色与右侧果实效果 |

## 7. 时间敏感用例

- 公开链长周期：原部署的持有人周期 30 天；审核再等 1 小时，且需满足 10 分钟最终性和区块条件。首个完整周期领取不能承诺当天完成。
- 原币退出：7 天；同时验证取消后状态与重新申请规则。
- 本地 Fork：在真实外部依赖上快进到边界前一秒/边界/边界后一秒，覆盖 30 天、7 天、root 窗口及领取期限。
- 不通过改现有主部署时间参数或篡改时间来让公开链用例虚假通过。需要快速演示版本时另列变体和审批，不将其代替原部署验收。

1. 短周期公开链功能通过：主流程真实上链、费用守恒、无未解决 P0/P1。
2. 长周期验证中/通过：明确列出尚待 30 天、7 天及其他时间条件的用例。
3. RH 生产就绪：另外完成真实股票、生产接收器/权限、生产部署交易大小与 Gas、RH 依赖、服务与生产门禁；Arbitrum 测试通过不自动获得该结论。
