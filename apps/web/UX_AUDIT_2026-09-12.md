# Frontend UX audit — 2026-09-12

Scope: homepage, Explore, token detail and trade, Create, Stake, Claim, Stats, shared navigation, dialogs, notices, loading, empty, and error states on the test frontend.

## Findings and changes

| # | Finding | Impact | Change | Status |
|---|---|---|---|---|
| 1 | Explore initially exposed loading and empty messages together. | Users could read the page as empty before loading finished; assistive technology could hear conflicting states. | Hide the empty state initially and give each stage one dedicated polite status. | Fixed |
| 2 | A large live region wrapped the full Explore directory. | Every card update could be announced as a large, noisy state change. | Limit live announcements to short loading, empty, and error messages. | Fixed |
| 3 | Directory and page failures often told users to wait or refresh without an action. | Recovery depended on users guessing what to do. | Add a local stage retry and a consistent page-level “Try again” action for terminal load errors. | Fixed |
| 4 | Error copy exposed implementation terms such as canonical route, snapshot, and PoolManager. | Users could not tell whether browsing or trading was affected. | Translate diagnostics to market data, trading route, and liquidity pool; state when details remain readable but trading is unavailable. | Fixed |
| 5 | Several labels and status messages used inconsistent title case. | The product felt less polished and longer messages were harder to scan. | Use sentence case across Explore, trade, Create, Stake, Claim, Stats, wallet, and transaction progress copy. | Fixed |
| 6 | The trade form rendered paired-asset names as buttons with no action. | The controls looked interactive and created dead keyboard stops. | Render them as descriptive text. | Fixed |
| 7 | Clicking the receive-side balance silently changed trade direction. | The result was surprising and its original label did not explain the action. | Give both balance actions explicit accessible names and tooltips, including the direction change. | Fixed |
| 8 | Trade activity tabs did not implement arrow-key navigation. | Keyboard users had to tab through every control and the tab pattern was incomplete. | Add roving tab focus plus Left, Right, Home, and End behavior. | Fixed |
| 9 | Global CSS removed visible focus from inputs, selects, and textareas. | Keyboard users could lose their position in forms and filters. | Restore a consistent high-contrast focus ring across interactive controls. | Fixed |
| 10 | The SPA had no skip link and did not move focus after navigation. | Keyboard and screen-reader users had to traverse the header again after each route change. | Add “Skip to main content,” a stable main target, and route-change focus management. | Fixed |
| 11 | Several icon and pagination targets were below comfortable touch size. | Mobile and motor-impaired users could miss the target. | Increase token-explorer, balance, and pagination controls to at least 32–36 px while preserving layout. | Fixed |
| 12 | The Stock picker could close while leaving focus in hidden content. | Keyboard focus could appear to disappear after Escape. | Return focus to the filter trigger and announce the selected filter in its accessible name. | Fixed |
| 13 | Stats did not visibly identify its testnet context. | Numbers could be mistaken for production data. | Label the page as testnet data and retain the 20-minute refresh note. Missing or stale values remain `Unavailable`. | Fixed |
| 14 | Explore used the abbreviation “MC” without explanation. | New users could miss that it means market capitalization. | Show “Market cap” in the card and accessible label. | Fixed |

## Verification

- Added focused checks for skip navigation, route focus, Explore state announcements and retry, trade control semantics, and tab keyboard behavior.
