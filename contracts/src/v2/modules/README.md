# Protocol modules

Canonical V2 modules described by `spec/v2_abi_surface.json` live here, including registries, factory, curve, vault, allocation, gauge, fee accounting, hook, graduation, locker, controller, and creator-revenue boundaries.

`MarketRegistryV2.sol` stores immutable market snapshots, initializes canonical runtime state, derives PoolKey/PoolId/fee-source views, and exposes only the frozen semantic launch/status transitions to immutable module callers. V2-C-305 extends its read-only surface with an immutable Router/Quoter-backed `canonicalRoute`: clients receive every market address, the predicted or deployed Locker, lifecycle/source version, and contract-derived Curve/v4 trading gates without reconstructing safety-critical PoolKeys. Its compiled artifact is checked against `IMarketRegistryV2`; this does not make the wider V2 protocol deployable.

`OfficialStockRegistryV2.sol` is the completed V2-C-102-A module. It append-only binds each nonzero Asset UID to one deployed canonical Stock Token, one deployed UserStockVault, frozen 6–18 decimals, and an admission status. UID, Token, and each Asset-to-Vault binding are write-once; multiple assets may share one Vault, while `vaultIdentity`, `vaultSchemaId`, and `vaultForSchema` enforce one canonical Vault per schema. Status follows `UNSET -> ACTIVE <-> PAUSED -> RETIRED` through selector-scoped AccessManager authorization.

`ApprovedQuoteRegistry.sol` is the completed V2-C-102-B module. It append-only stores chain-bound, content-addressed native/ERC-20 Quote configurations with frozen baseline, decimals, phantom amount, graduation threshold, and economics hash. Native is exactly `address(0)` with 18 decimals; ERC-20 admission requires deployed code and a matching live `decimals()` result in the frozen 6–18 domain. Status follows `UNSET -> ACTIVE <-> PAUSED -> RETIRED` through selector-scoped AccessManager authorization. Exact-transfer behavior, rebasing risk, and proxy/implementation fingerprints remain deployment-preflight evidence.

`PonsBaselineRegistry.sol` is part of completed V2-C-102-C. It append-only freezes the reference chain/factory runtime identity, launch configuration, supply, curve fee, zero PoolKey fee, tick spacing, behavior-vector root, and admission status. `launchConfigId == 0` remains valid, while reference runtime code is checked at registration.

`LaunchTemplateRegistry.sol` completes V2-C-102-C. It append-only freezes deployed Token/Curve/Gauge/Hook/Locker component code identities, GraduationExecutor, fee policy, and exact `V2-EXEC-4` identity. The canonical template hash excludes mutable status, Hook address permissions must equal `0x2044`, and all code-bearing addresses are validated at registration. Both C-102-C registries use the same terminal status machine and selector-scoped AccessManager delays as the other configuration registries.

`LaunchConfigResolver.sol` is the typed, read-only management facade over ApprovedQuote, PonsBaseline, and LaunchTemplate registries. It freezes the three registry addresses, forwards every read without caching, and deliberately remains outside the Factory's mandatory launch path so convenience aggregation does not become a new configuration authority or availability dependency.

`TickerMemeTokenV2.sol` completes V2-C-103-A. It is a standard 18-decimal ERC-20 with immutable market, creator, deploying Factory, metadata URI, and initial-supply identity. Construction mints the entire nonzero supply directly to the predicted Curve; the runtime exposes no mint, burn, tax, rebase, blacklist, pause, metadata mutation, role, or V1 emission path.

`CreatorRevenueRegistry.sol` completes V2-C-104-A. The immutable Factory initializes epoch one only after the market snapshot exists, and each current beneficiary can append exactly one future beneficiary epoch. A pre-graduation transfer atomically sweeps the exact registered Curve and verifies zero residual accrual before incrementing; historical beneficiaries remain immutable, and reentrancy cannot overwrite an epoch.

`TickerGardenFactoryV2.sol` completes V2-C-105. It validates the four ACTIVE Registry snapshots and exact economics, derives the typed market and component identities, deploys the fixed-supply Token and transient-snapshot Curve through their codehash-pinned typed delegate targets, and deploys the Gauge as an OpenZeppelin deterministic immutable-args clone of one codehash-pinned implementation. The Factory remains the CREATE2 deployer, verifies the clone's complete identity after deployment, and commits market registration, creator epoch initialization, exact immutable launch-fee delivery, and the sole `MarketCreated` event atomically.

`PonsCompatibleCurve.sol` completes V2-C-107 and supplies the C303-D escrow evidence. Its CREATE2 code depends only on the Factory and reads a transient Factory snapshot during construction, avoiding the Token↔Curve prediction cycle without adding a public initializer. It verifies the prefunded fixed Meme supply and the MarketRegistry-bound GraduationExecutor, binds every trade to the exact registered market, maintains balance-independent tracked reserves, performs strict native/ERC-20 exact-delta settlement, refunds unused Quote to the caller, and permanently closes trading at the reserved floor. The final buy atomically freezes the exact graduation Quote/Meme amounts in a supplemental read-only record, sweeps fees, transfers only tracked assets to the Executor, commits `Swept`, and catches only the automatic graduation subcall so a failed pool creation retains auditable retry/rescue evidence. Final product composition still depends on the C304 Locker implementation.

`UserStockVault.sol` completes V2-C-201. Each non-upgradeable instance freezes a MultiAsset schema and the exact OfficialStockRegistry, MarketRegistry, and AllocationManager; the Registry permits one canonical Vault per schema. Every operation resolves the canonical Token from an explicit Asset UID, and every principal/allocation ledger is keyed by that UID. It provides exact-arrival deposits, caller-only exact-delta free withdrawals, authoritative asset/user/market allocation accounting, Manager-only lock/release/move operations, and caller-only terminal Emergency release that never calls a Gauge or transfers principal directly.

`AllocationManager.sol` completes V2-C-202. It exposes exactly the six canonical caller-only mutations, resolves each market's Asset UID and canonical shared Vault, coordinates that Vault with per-market Gauges, enforces increase/exit/migration lifecycle gates and raw-unit minimums, and keeps deposits, allocations, exits, and no-overlap same-Asset migrations atomic without ever taking custody of STOCK.

`MemeStockGauge.sol` completes V2-C-204. One fixed, non-upgradeable implementation serves deterministic per-market immutable-args clones. Each 301-byte clone freezes one market, Asset UID, Quote configuration, Manager, FeeVault, Controller, Quote asset, and Meme token in runtime code with no initializer, while owning isolated reward, position, activation, and Emergency storage. Its canonical caller-only surface composes the bounded activation wheel, 24-hour whole-position lock, dual-asset accumulators, active/pending historical settlement, claim consumption, lifecycle gating, and permanent Controller-only Emergency disablement without taking custody of STOCK or fee assets.

`MarketController.sol` completes V2-C-401. Its immutable AccessManager gates immediate pause, 24-hour delayed unpause, and 48-hour delayed retirement, while `MarketRegistryV2` remains the sole runtime authority for status timestamps and the continuous restricted interval. The allocation view is derived only from `PoolCreated + ACTIVE + Asset ACTIVE`; Quote admission changes do not silently rewrite historical markets, and ordinary pause or retirement does not add a claim, maturity, or principal-withdrawal veto.

`ProtocolFeeVault.sol` composes the V4 and Curve exact-arrival credits, dual-asset liabilities and fixed-recipient claims with Emergency cap freezing, challengeable Recovery roots, and caller-bound capped Merkle claims. Its Controller dependency may be a precomputed future deployment address, resolving the immutable Vault/Controller construction cycle without an initializer.

`LaunchLocker.sol` completes V2-C-304. Each CREATE2 instance permanently binds one market, canonical pool, full-range Position NFT, and ordered currency pair. Its only mutation is permissionless compounding: it collects fees from that exact NFT, derives an explicit liquidity amount from the canonical Slot0 and locked balances, and increases only the same position. Native/ERC-20 settlement is exact, temporary Permit2 allowances are revoked, unpaired balances remain isolated in the Locker, and no withdrawal, NFT approval/transfer, arbitrary execution, admin, or recovery surface exists.

`GraduationExecutor.sol` completes the V2-C-303 product composition after the final Locker code is available. It uses a runtime code store to keep the exact LaunchLocker creation code deployable without inflating the Executor runtime, while retaining the guarded Curve entry, permissionless retry, fixed-recipient rescue, canonical v4 initialize/mint/settle flow, Hook activation, and atomic Registry commit.
