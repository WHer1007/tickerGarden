# Shared V2 definitions

This directory contains product-neutral code reused across V2 modules.

- `ImmutableAccessManaged.sol` freezes the AccessManager address and selector-scoped authorization path.
- `V2Identifiers.sol` is the canonical schema-v1 market ID and component-salt implementation.
- `V2Create2.sol` is the shared EIP-1014 prediction and zero-value CREATE2 deployment path for Factory and GraduationExecutor.
- `V2MarketEconomics.sol` hashes immutable Pons baseline, fee-policy, and expected-economics content.
- `V2FactoryValidation.sol` resolves ACTIVE Registry snapshots, authenticates direct/Router creator identity, reads the asset's Registry-configured raw-unit `minimumAllocation`, and verifies caller-supplied `V2-EXEC-4` economics; the former ten-whole-STOCK saturation is removed.
- `MemeStockGaugeClone.sol` validates, predicts, deploys, and decodes the fixed eight-word `GaugeIdentity` used by deterministic OpenZeppelin immutable-args clones. Prediction permits the not-yet-deployed CREATE2 Meme address, while actual deployment requires live Token, Quote, Manager, FeeVault, and Controller code and an exact 301-byte instance runtime.
- `LaunchAndBuyRouterNative.sol` provides the native-Quote half of the canonical atomic launch-and-buy flow. It binds the Factory to the expected Quote Registry, forwards only the exact launch fee into creation, sends the first buy to the new Curve, returns tail-fill refunds only to the outer creator, and preserves any forced historic Router balance.
- `LaunchAndBuyRouterERC20.sol` adds the ERC-20 Quote half without extending the canonical ABI. It pulls an exact first-buy balance from the creator, grants only the new Curve an exact one-use allowance, rejects anomalous token returns or deltas, returns partial-fill Quote only to the creator, and proves no transaction-created token or native balance remains in the Router.
- `UserStockVaultIdentity.sol` freezes OfficialStockRegistry, MarketRegistry, AllocationManager, and the MultiAsset schema before registry admission. Every operation resolves its explicit Asset UID to the canonical STOCK and revalidates the Registry's write-once Asset-to-Vault plus market-to-asset bindings; there is no public initializer or token-address input.
- `UserStockVaultDeposits.sol` adds reusable non-reentrant, exact-arrival STOCK deposit accounting partitioned by Asset UID. It rejects zero/invalid accounts, inactive assets, anomalous token returns, fee-on-transfer/rebase deltas, and callbacks without ever routing principal through AllocationManager.
- `UserStockVaultLedger.sol` adds the authoritative asset/user/market allocation ledger. Manager-only lock, release, and move operations preserve per-asset user, market, and total aggregation while rejecting cross-asset markets, duplicate source/target markets, and principal reuse.
- `UserStockVaultExits.sol` adds caller-only free-principal withdrawal with exact outbound balance deltas and terminal Emergency allocation release. Neither path accepts a recipient; force release reads only Registry terminal state and never calls a Gauge.
- `AllocationManagerIncreases.sol` provides the caller-bound allocate/increase path for the eventual AllocationManager. It resolves canonical Vault/Gauge components from Registries, gates on PoolCreated/Market ACTIVE/Asset ACTIVE, enforces the current Registry raw-unit `minimumAllocation`, and atomically orders checkpoint, settlement, Vault locking, and 30-second/24-hour Gauge scheduling.
- `AllocationManagerDecreases.sol` adds caller-bound decrease/close behavior. It permits matured normal exits from ACTIVE, PAUSED, or RETIRED PoolCreated markets, rejects Emergency, enforces the current minimum only for nonzero remaining positions, and atomically removes Gauge weight before releasing the exact Vault allocation to free balance; full normal exit and emergency escape are never blocked by the minimum.
- `AllocationManagerDeposits.sol` adds the caller-bound `depositAndAllocate` composition. It validates the target first, makes the canonical Vault pull exact STOCK directly from the outer caller, then reuses the guarded increase pipeline so every deposit, ledger update, and pending schedule commits or reverts together.
- `AllocationManagerMigrations.sol` atomically migrates one caller-owned, mature allocation between same-Asset markets. It settles both Gauges at their old weights, requires source remainders and target results to meet the current Registry minimum when nonzero, removes the source before moving the Vault ledger, then schedules the exact amount as target pending while preserving the source lock and resetting the target timers. Existing positions below a newly raised minimum are not forcibly closed; they must be topped up or fully exited.
- `MemeStockGaugeActivationWheel.sol` implements the fixed 32-slot activation core with absolute second-level generations, same-generation aggregation, collision-safe reuse, exact mature-boundary processing, and constant-size effective-weight scans. Snapshot persistence is attached through a bounded internal hook for the next Gauge layer.
- `MemeStockGaugeActivationSnapshots.sol` persists immutable dual-accumulator snapshots by absolute generation and lazily merges processed pending weight into each user position. Snapshot references are decremented without historical scans and deleted only after the last user materializes; concrete reward/remainder arithmetic remains isolated behind the C204 settlement hook.
- `MemeStockGaugePendingPositions.sol` enforces one pending aggregate per user. It checkpoints first, materializes processed pending before a new schedule, or atomically unschedules and re-buckets future pending while resetting the whole-position 24-hour lock and preserving exactly one reference.
- `MemeStockGaugeLockedPositions.sol` defensively rechecks the whole-position 24-hour lock at the Gauge boundary, materializes and settles the full old weight before removal, preserves the lock on partial exits, clears it on full close, and leaves reward debt/remainders intact.
- `MemeStockGaugeAccumulators.sol` maintains independent Quote/Meme `1e27` indices and pool remainders with full-precision `mulDiv`/`mulmod`, exposes composable user-remainder settlement and claimable-consumption primitives, and checkpoints matured weight before every credit.
- `MemeStockGaugeSettlements.sol` composes active weight and processed-pending snapshot indices into exact per-user Quote/Meme settlement. It preserves fractional debt across full closes, settles before every weight change, and previews claimable rewards without mutating lazy materialization state.
- `TickerGardenMemeHookBinding.sol` freezes the Hook's `0x2044` CREATE2 permission bits and immutable dependencies, registers only the Registry's complete canonical PoolKey at the checked next source version, and provides the active callback source guard.
- `TickerGardenMemeHookLifecycle.sol` adds the one-way `NONE -> EXPECTED -> INITIALIZE_SEEN -> ACTIVE -> DISABLED` pool lifecycle. Initialization and activation remain inside the atomic graduation call, while emergency disable accepts only the exact restricted PoolCreated source before Registry invalidation.
- `TickerGardenMemeHookFeeCalculation.sol` decodes the locked v4 packed BalanceDelta, chooses the unspecified currency across all four exact-input/output directions, safely handles the full int128 domain, and prepares the canonical 1% split, pool nonce, fee-policy hash, and v4 fee ID for the final atomic afterSwap path. Under `V2-EXEC-4`, any active STOCK makes Staker's share a fixed 50% of non-LP (about 40% of total fee), allocated by active raw-unit stake; with no active stake, Creator and Platform each receive half of non-LP, and the former 10 STOCK linear/saturation switch is absent.
- `TickerGardenMemeHookFeeExecution.sol` reads the locked v4-core Slot0 through `StateLibrary`, fails closed on any LP or packed protocol fee, then atomically opens an exact-arrival FeeVault credit, donates the LP share in the selected currency slot, takes the non-LP share directly into the Vault, finalizes the canonical record, and returns the full fee delta without leaving Hook custody.
- `ProtocolFeeVaultRecoveryCaps.sol` freezes the exact Quote/Meme staker liabilities, snapshot block, and state hash during the Controller's atomic Emergency transition; callers cannot supply either cap.
- `ProtocolFeeVaultRecoveryRoots.sol` provides the delayed proposal, Guardian cancellation, permissionless 48-hour finalization, monotonic nonce, and terminal root lifecycle bound to one frozen market epoch and canonical fee asset.
- `ProtocolFeeVaultRecoveryClaims.sol` verifies the canonical domain-separated double-hash Merkle leaf, fixes payment to the caller, enforces one claim per market/epoch/asset/user, and debits only the frozen staker liability under declared-total and cap bounds.
- `GraduationExecutorEntry.sol` authenticates the Registry's exact Curve, admits only `Swept + ACTIVE`, and requires every successful automatic-graduation return to have atomically committed one nonzero PoolCreated source while preserving `sweptAt` and advancing `sourceVersion` exactly once.
- `GraduationExecutorAssetAccounting.sol` binds frozen Quote economics to each swept market, derives pool Meme and permanently locked excess with full-precision Pons math, and requires the concrete pool/Locker path to consume the recorded Quote and Meme escrow exactly before emitting `PoolGraduated`; unrelated executor balances are never folded into a market plan.
- `GraduationPoolMath.sol` derives the canonical v4 PoolId, currency amounts, Q192/Q128 initial square-root price, full-range ticks, initial tick, and bounded liquidity directly from swept assets using the locked official v4 math libraries; malformed keys, int128 overflow, out-of-range price, and zero/excess liquidity fail closed before pool initialization.
- `LaunchLockerBinding.sol` keeps Factory-time CREATE2 prediction independent of the global PositionManager counter while binding each deployed Locker to the current prospective tokenId and canonical market pool in its constructor; the final Executor must mint that exact NFT directly to the Locker or atomically revert.
- `LaunchLockerCustody.sol` freezes that Locker's canonical two-currency custody domain, exposes only read-only locked balances, accepts ordinary native value only for native-Quote pools, and deliberately provides no initializer, NFT/asset transfer, approval, arbitrary-call, admin, or recovery surface.
- `GraduationExecutorPoolExecution.sol` deploys that Locker from the Executor CREATE2 namespace, routes deterministic Quote/Meme dust, performs the official v4 `MINT_POSITION + SETTLE_PAIR` flow with exact native value and Permit2 limits, verifies the resulting NFT/key/range/liquidity, then atomically activates the Hook and commits PoolCreated.
- `GraduationExecutorRetryAndRescue.sol` reads the exact immutable escrow amounts frozen by each registered Curve, exposes permissionless retry through the same atomic pool path, and after the inclusive seven-day boundary moves only that market's native/ERC-20 escrow to a deployment-frozen rescue distributor before atomically committing `Rescued`. Caller-selected recipients and aggregate-balance inference are absent.
- `V2Scaffold.sol` retains the isolated namespace and execution-spec compile marker.

The identity, economics, validation, and CREATE2 libraries are covered by frozen synthetic vectors, Registry-drift tests, and a local prediction-versus-deployment test. Final component constructor arguments, init-code hashes, deployer addresses, atomic Registry writes, and production manifest evidence remain integration and deployment responsibilities.
